# Постоянные инструкции для работы над HomeAiCore

Правила владельца, повторно подтверждены 20 октября 2026 года. Прочитать в начале каждой новой сессии работы с проектом, до изменения кода, Git или релизов. Правила действуют для HomeAiCore и связанных репозиториев модулей, если пользователь явно не поручил иное в текущей задаче.

## Git

- Работать непосредственно в существующей ветке `main`.
- Не создавать отдельные ветки: feature, fix, release, временные или любые другие.
- Не создавать Pull Request, в том числе draft PR. Не передавать работу агенту или инструменту, который автоматически создаёт ветку/PR.
- До изменений читать актуальный код и проверять состояние рабочей копии и удалённой `main`. Сохранять чужие и незакоммиченные изменения. Не применять force push, reset или перезапись истории для обхода конфликтов.
- Выполнять необходимые проверки до отправки собственных изменений в `main`. При невозможности прямой записи сообщить конкретное препятствие, а не создавать ветку или PR без отдельного поручения.

## Сборки и релизы

- Не создавать черновики GitHub Releases и не оставлять результат порученного выпуска в состоянии draft. Это относится также к workflow, скриптам и делегированным инструментам.
- В рамках порученного выпуска после успешных обязательных проверок публиковать релиз с `draft=false`. Не обходить тесты, проверку артефактов, контрольные суммы и обязательную подпись ради публикации.
- Если проверки не прошли или выпуск заблокирован, не публиковать неисправную сборку и не создавать черновик вместо результата. Сообщить, что именно не выполнено.
- После выпуска проверить реальный статус релиза и наличие артефактов. Не называть коммит, локальную сборку, артефакт CI или draft опубликованным релизом.
- Эта инструкция сама по себе не является поручением публиковать старые или посторонние релизы, устанавливать обновления на сервер или менять работающие сервисы. Для таких действий нужен соответствующий запрос пользователя.

## Обязательное поведение модулей в левом меню

Требование владельца: **после успешной установки каждый модуль автоматически появляется в левом меню HomeAiCore, без ручного добавления пользователем**. Это часть установки модуля, а не необязательное оформление.

- Правило распространяется на все модули, включая Home Assistant, Frigate, NVR, AI Agent и будущие модули.
- Пункт появляется после завершения установки без ручного редактирования manifest, повторной установки, перезапуска Core или обязательного обновления страницы. Он сохраняется после перезагрузки страницы и нового входа.
- Пустое или отсутствующее `ui.navigation` не должно делать установленный модуль невидимым: ядро обязано предоставить стандартный пункт по ID и имени из реестра установленных модулей. Исправление должно работать и для уже установленных модулей со старым manifest, а не только для новых записей каталога.
- Пункт ведёт на существующую страницу модуля или его управления, а не на заглушку «маршрут недоступен». Для модуля с отдельным веб-интерфейсом должен быть предусмотрен рабочий переход к нему.
- Остановленный или временно недоступный установленный модуль не исчезает из меню: отображается его состояние. После удаления модуля его пункт автоматически убирается. Неустановленные предложения каталога не выдаются за установленные модули.
- Не создавать дубликаты пунктов при повторном чтении состояния, обновлении модуля или наличии явно заданной навигации.
- Соблюдать существующие права доступа к модулю. Автоматическое появление в меню не является разрешением обходить авторизацию или открывать модуль всем пользователям.
- При доработке установки или навигации обязательны регрессионные проверки: установка → появление пункта без перезагрузки; пустое `ui.navigation`; ранее установленный модуль; остановка и повторный запуск; обновление страницы/новый вход; удаление; отсутствие дубликатов; пользователь без права доступа; работоспособность перехода.
- Не считать интеграцию модуля завершённой только по успешному запуску контейнера: проверить, что модуль виден в левом меню и открывается из него. В отчёте различать сохранение этого требования, исправление кода и фактическую проверку на установленной системе.

## Начало нового чата

Сначала прочитать этот файл и сохранить эти ограничения в рабочем плане. Не возвращаться к отдельным веткам, PR или черновикам релизов как к стандартному процессу. Не просить пользователя повторять уже записанное предпочтение. При работе с модулями обязательно учитывать автоматическое появление установленных модулей в левом меню.
