
## Automatic installed-module navigation

- Every installed module receives a sidebar entry from its saved registry record, including existing Home Assistant installations whose manifest has an empty `ui` section. Reinstalling the module or changing its configuration is not required.
- Stopped and errored modules remain visible with their status and a working management page. Removed modules disappear; module permissions remain enforced.
- Fixed a lost-refresh race: when installation/removal finishes during an in-flight navigation request, a follow-up refresh is queued immediately rather than waiting for the next periodic poll.
- Navigation also refreshes when the browser reconnects, returns to the foreground or gains focus. Requests from a previous signed-in session are cancelled.
- Added production-bundle Chromium regressions for catalog installation, the existing empty Home Assistant manifest, stop/start/error, page reload, sign-out/sign-in, removal, permission filtering, reconnect and stale-request recovery. These use isolated API fixtures, not the production server.

### Existing installations

Update HomeAiCore to this version, then load the updated interface. Home Assistant appears automatically from the existing registry; it does not need to be removed or installed again. Its sidebar entry opens module management with the link to its own web interface on port 8123.

This release does not automatically update Home Assistant or change its container/configuration. Standard Core update backups and signature verification still apply.
