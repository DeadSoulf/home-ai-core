# AI Agent 0.3 — раздельные CPU и GPU-образы

CPU-образ по умолчанию: `ghcr.io/deadsoulf/home-ai-core-ai@sha256:f293ac8deead89561df585b13516b25999bd4a1b103725235c80608919ab86a6`.
Дополнительный GPU-образ: `ghcr.io/deadsoulf/home-ai-core-ai@sha256:df8587d727e1e185c916e7f34c21516d08fb0cee272cb71f54d3a4e8c0bc22c6`.

Оба закреплены по настоящим digest OCI index, содержат одну версию AI Agent 0.3.0 и один контракт `/data`. GPU-образ больше не нужен для обычной установки.

## Процедура

1. Установить 0.3.0 из официального каталога Core. Docker скачивает только компактный CPU-образ; Ollama запускается и самостоятельно начинает загрузку `qwen3:0.6b`.
2. Core опрашивает локальное оборудование. GPU должна быть видна в ОС, а NVIDIA драйвер и NVIDIA Container Toolkit должны быть установлены и исправны.
3. Администратор во вкладке «Локальный AI» выбирает «Загрузить GPU-компоненты». Отдельное задание `module.gpu.prepare` скачивает **только** закреплённый GPU-образ. Его текущий этап/слой доступен в «Модули → Операции». CPU-контейнер продолжает работать.
4. После загрузки администратор подтверждает набор выбранных NVIDIA GPU. Helper проверяет PCI→UUID, использует соответствующий закреплённый образ и создаёт временный контейнер на прежнем `/data`. Затем проверяет его здоровье и видимость GPU. При ошибке пытается вернуть прежний контейнер.
5. При снятии всех GPU переключение возвращается на компактный CPU-образ из локального кэша. Модели и диалоги хранятся в `/data` и не удаляются.

Ограничения: автоматической установки драйверов и NVIDIA Container Toolkit нет — это привилегированные изменения хоста; AMD/Intel GPU в версии 0.3.0 только обнаруживаются; сама загрузка `qwen3:0.6b` происходит при первом старте и требует доступного Ollama Registry. Операции на реальных GPU нужно отдельно проверить на сервере с NVIDIA.

Безопасность: клиент не может указать адрес OCI-образа или Docker-флаги; выбор ограничен двумя закреплёнными digest, все управляющие запросы требуют `modules.manage` и CSRF для cookie-сессий. GPU-образ загружается без остановки AI. Аварийный перезапуск во время самой замены требует проверки статуса контейнера; он не должен автоматически повторять привилегированную операцию.

## Переход со старой версии

Core не обновляет установленный модуль 0.2.0 на другой digest автоматически. Запись установки в состоянии `registered` привязана к старому манифесту. Для перехода используйте предусмотренную UI-процедуру удаления записи и установки нового manifest; **сначала сохраните резервную копию** `/var/lib/home-ai-modules/ai.agent` и не удаляйте саму папку данных.
