# NVR: живой просмотр, удаление камер и выбор видео-диска

## Страница NVR в HOME AI Core

После установки обновлённого Core слева открывается **NVR**.
Доступны вкладки:

- **Камеры** — добавление, запуск и остановка записи, перезапуск, а
  также кнопка **«Удалить камеру»** с обязательным подтверждением.
- **Просмотр в реальном времени** — выбор сохранённой камеры,
  запуск HLS-видеопотока и остановка просмотра.
- **Поиск камер** — обнаружение RTSP/ONVIF/SSDP/mDNS и характерных
  сетевых портов.
- **Архив записей** — воспроизведение с HTTP Range без открытия порта NVR.

Прямой просмотр сохранённой камеры и безопасное удаление требуют
**NVR версии 1.1.3 или новее**. Версия 1.1.2 сохраняла SQL-индекс архива
недостаточно безопасно при удалении записи камеры, поэтому Core
отклоняет такую операцию, вместо риска потери истории.

В NVR 1.1.3 кнопка удаления скрывает камеру, останавливает её запись,
но оставляет файлы и индекс видеозаписей. Архив и дальше подчиняется
настроенному в NVR сроку хранения. Операцию **«Удалить и очистить архив»**
новый Core не предлагает.

HLS выдаётся только через авторизованный Core API. Камера хранит пароль
внутри NVR; веб-интерфейс не получает пароль или исходную RTSP-строку.
Транскодирование может загружать процессор. При закрытии страницы
веб-интерфейс по возможности останавливает созданный поток. Не открывайте
порт NVR 8090 в Интернет.

## Если уже установлен NVR 1.1.2

Официальный каталог обновлён до закреплённого NVR 1.1.3. Если текущий
Core блокирует смену образа для уже установленного модуля, безопасная
ручная процедура:

1. Убедиться в резервной копии каталога
   `/var/lib/home-ai-modules/nvr.module` (включая `nvr.db`).
2. Остановить запись камер и закрыть прямой просмотр.
3. В «Установленные модули» выбрать **«Удалить модуль»**, **не**
   «удалить данные». Core удалит только Docker-контейнер и запись в
   реестре модулей, сохранив каталог данных.
4. В официальном каталоге установить NVR 1.1.3, используя прежний ID
   `nvr.module`. Контейнер снова получает те же файлы `/data`.
5. Проверить камеры, журнал и архив. В NVR 1.1.3 миграция базы
   добавляет soft-delete, не переписывая список записей.

Не следует удалять Docker volumes или вручную очищать `/data`.

## Выбор диска для видео: подготовительный этап

В разделе **«Файлы → Хранилище»** появился блок
**«Диски для видеоархива NVR»**. Можно назначить NVR существующий
несистемный раздел `ext4`/`xfs`, либо открыть в «Система → Хранилище»
мастер создания раздела и выбрать назначение **«NVR · Видеоархив»**.

Создание раздела по-прежнему требует явного подтверждения, а назначение
существующего диска **не форматирует** его. Назначение хранится отдельно
от файловых пулов, существующие назначения Files сохраняются миграцией
базы и не подменяются разделами NVR. В UI можно отдельно смонтировать
выделенный NVR-раздел.

**Назначение диска само по себе не переносит записи.** Для существующего
NVR после обновления Core откройте **«Модули → Установленные → NVR»** и
нажмите **«Подключить назначенный диск NVR»**. Подтвердите остановку
записи и перенос: операция выполняется фоновым заданием и проверяет UUID,
наличие отдельного монтирования, целостность копии, состояние здоровья
контейнера и фактическую файловую систему `/data`.

HomeAiCore останавливает контейнер на время переноса, сохраняет исходный
каталог как резервную копию рядом с ним и привязывает `/data` к
`/mnt/home-ai-core/<mount>/.home-ai-nvr-data` через постоянную ссылку.
При ошибке запуска выполняется попытка отката к исходному каталогу.
Если назначенный диск отключён или UUID не совпадает, новый запуск через
Core блокируется вместо записи на системный раздел. При автоматическом
запуске Docker отсутствие каталога назначения должно вызывать ошибку
bind mount, а не создание системного каталога.

Перенос допускается только при **одном** назначенном диске NVR. Не очищайте
оригинальный каталог и не удаляйте резервную копию до успешной реальной
проверки просмотра и записи архива, включая перезагрузку сервера.
Смена образа NVR на другую версию по-прежнему требует отдельного
механизма безопасного обновления модулей.

## Проверки

CI проверяет Go API и авторизацию/CSRF, запрет удаления камер со старой
версией, неконтролируемые URL потоков, миграцию storage_purposes без
потери существующих Files-назначений, типы React и сборку клиента.
Реальная проверка камер, чтения архива с отдельного диска и восстановления
после перезапуска Docker требует испытаний на хосте.
