# Приватное обновление NVR 1.1.6 с HCNetSDK 6.1.11.40

## Почему новый NVR не заменяет публичный каталог

Официальный общедоступный каталог `DeadSoulf/home-ai-core_modules/catalog.json`
сохраняет стабильный NVR 1.1.4. Новый образ
`ghcr.io/deadsoulf/home-ai-core_dvr-sdk611@sha256:d61856e76052d6413eb2aed9bee72b38c077a0c7bf35445094d248c571d3961e`
содержит библиотеки Hikvision из архива производителя и остаётся закрытым.
Заменить общедоступный NVR ссылкой на закрытый пакет нельзя: обычные
пользователи перестанут иметь возможность его установить.

Для принадлежащего владельцу сервера HomeAiCore добавлен **опциональный
закрытый канал обновления NVR**, который использует существующий механизм
обновления с проверкой состояния и откатом. При правильных учётных
данных он показывает версию 1.1.6 в тех же разделах
**Модули → Установленные → Проверить обновления** и **Каталог модулей**.

Источник закрытого манифеста:
`DeadSoulf/home-ai-bridge/modules/nvr.sdk611.manifest.json`.

## Требования доступа

Включение выполняется **только владельцем сервера**:

1. Использовать персональный токен GitHub с минимальными необходимыми
   разрешениями на чтение приватного репозитория `home-ai-bridge`
   и закрытого GHCR-пакета NVR (`repo` и `read:packages` для
   подходящего classic PAT).
2. Сохранить секрет только на сервере, например в
   `/etc/home-ai-core/private-registry.env`, с правами `0600`
   и владельцем `root`. **Не добавлять токен в Git, системные
   журналы и файлы веб-интерфейса**.
3. Задать переменные окружения обоим systemd-сервисам
   `home-ai-core.service` и `home-ai-core-updater.service` с помощью
   защищённого `EnvironmentFile`:

```ini
HOME_AI_MODULE_PRIVATE_SDK611=1
HOME_AI_MODULE_REGISTRY_USER=DeadSoulf
HOME_AI_MODULE_CATALOG_TOKEN=<YOUR_READ_ONLY_GITHUB_PACKAGE_TOKEN>
```

Значение `HOME_AI_MODULE_CATALOG_TOKEN` должно быть доступно и Core (для
загрузки приватного манифеста), и привилегированному updater (для
`docker login ghcr.io` во временном `DOCKER_CONFIG`).
При смене настроек понадобится перезапуск соответствующих служб.

Если токен отсутствует, некорректен или не имеет доступа к приватному
репозиторию, Core **оставит публичный NVR 1.1.4**, а веб-интерфейс
покажет ошибку доступа. Приватные токены не должны передаваться
браузеру и не записываются в постоянный Docker config.

## Безопасная последовательность обновления

1. Сначала убедиться, что текущие записи NVR действительно находятся на
   назначенном смонтированном диске, проверить UUID и сделать резервную
   копию `nvr.db` и важного архива.
2. Установить Core с поддержкой приватного каталога.
3. Проверить `Модули → Установленные → NVR`. При правильной
   конфигурации увидите **1.1.4 → 1.1.6**.
4. Нажать **Обновить модуль** и дождаться проверки нового контейнера.
   При сбое новый контейнер должен быть отвергнут и выполнен откат.
5. Убедиться в работе реальных камер, видеозаписи и восстановлении после
   перезапуска до удаления резервных копий.

**Не выполняйте установку без доступа к закрытому пакету.**
Не открывайте GHCR-пакет публично, не убедившись в праве распространять
библиотеки Hikvision. Расширенные функции SDK (голос, тревоги, архив
устройства) в данной версии ещё ограничены; локальный архив NVR и
RTSP/Hikvision-видеозапись сохраняются.
