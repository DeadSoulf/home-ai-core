# HOME AI Core — поиск IP-камер разных производителей

## Доступ

Включённый NVR → вкладка **«Поиск камер»** (право `modules.manage`).
Пользователь выбирает сеть из списка локальных интерфейсов HOME AI Core и
нажимает **«Найти камеры»**. Поиск не начинается автоматически при открытии страницы.

Поиск выполняется **на хосте Core**, а не внутри Docker-контейнера NVR:
обычная Docker bridge-сеть не может надёжно принимать широковещательные
объявления камер из физической LAN. Открывать порт NVR 8090 наружу не нужно.

## Какие способы используются

1. **ONVIF WS-Discovery**: UDP multicast 239.255.255.250:3702, запрос
   NetworkVideoTransmitter и ответы ProbeMatch. Без логина, ONVIF не обязателен.
2. **SSDP/UPnP**: UDP multicast 239.255.255.250:1900. Результаты
   фильтруются по признакам IP-камер, чтобы не показывать обычные роутеры.
3. **mDNS**: запросы `_rtsp._tcp.local`, `_onvif._tcp.local`
   на 224.0.0.251:5353; ответы с учётом DNS-сжатия.
4. **RTSP**: ограниченная TCP-проверка портов 554, 8554 через метод OPTIONS,
   без передачи паролей. Даже ответ 401 подтверждает наличие RTSP-сервера.
5. **Сервисные порты производителей**: 8000 (часто Hikvision/HCNetSDK),
   37777 (часто Dahua-совместимые), 34567 (часто Xiongmai/XMEye).
   Такой открытый порт сам по себе **не доказывает производителя или наличие камеры**.
6. **HTTP/HTTPS**: чтение заголовков на 80/443 (включая самоподписанные
   HTTPS-устройства, только для анонимного определения сервиса).
   Учитываются признаки IP-камер и названия производителей; логины не отправляются.

Одинаковые IP объединяются. В карточке устройства показаны предполагаемый
производитель, найденные протоколы, IP и уровень уверенности. Сервис
`RTSP` — это не готовая ссылка на поток: путь, канал и учётные данные
отличаются у производителей и моделей.

Кнопка **«Настроить подключение»** открывает существующую форму добавления
камеры. Для подтверждённой Hikvision с сервисом HCNetSDK можно заполнить
учётные данные и канал; для остальных используется универсальный RTSP.
Предложенный RTSP-адрес является основой для ручной настройки, а **не
автоматически проверенным каналом видеозаписи**.

## Безопасность

- Поиск выполняется **только по запросу пользователя** с `modules.manage`;
  мутации из браузера проверяются CSRF и фиксируются в журнале аудита.
- Выбрать произвольный CIDR невозможно: API принимает только точный ID
  сети, только что обнаруженной на прямо подключённом хостовом интерфейсе.
- Приватный IPv4, не более /24 за один запуск; Docker bridge и виртуальные
  контейнерные сети исключаются из списка.
- Максимум 64 параллельных TCP-работников, ограничение времени 15 секунд.
  Один поиск одновременно, минимальный интервал 10 секунд между запусками.
- Ни перебора паролей, ни сканирования Интернета, ни пробных изменений
  параметров камер, ни автоматического добавления в NVR.
- Ответы устройств не используются для сетевых переходов или скачивания
  произвольных URL. Пароли и RTSP-строки с секретами не включаются в
  результаты сканирования.
- Состояние самого модуля NVR и каталог записей не изменяются во время
  поиска.

## Что поиск не может гарантировать

Нет универсального способа обнаружения **каждой модели каждого
производителя**: некоторые камеры отключают multicast, закрывают порты,
не поддерживают RTSP/ONVIF, располагаются за NVR/NAT или в другой VLAN.
Проприетарные протоколы активации (например Hikvision SADP) не эмулируются.
Поиск не обходит сетевые ACL, парольные защиты и ограничения производителя.

Если камера не найдена, можно перейти во вкладку **«Камеры»** и вручную
добавить Hikvision через HCNetSDK или камеру любой марки с доступным RTSP.

## Тестирование

Unit-тесты проверяют private CIDR и ограничение /24, WS-Discovery,
SSDP, mDNS, RTSP, HTTP/HTTPS-распознавание и защиту DNS-сжатия,
а также авторизацию, CSRF, ограничение частоты и отказ в сканировании
произвольного адресного пространства.

Интеграционные испытания на реальных камерах из разных сетей и VLAN должны
проводиться отдельно на рабочем сервере.
