# AI Agent — интеграция с Home-AI-Core

## Цель

При установке и включении модуля `ai.agent` пункт бокового меню
`/modules/ai.agent` должен открывать полноценную страницу Core, а не заглушку.
Веб-порт контейнера **не публикуется** на хосте или в Интернете.

## Контракт (начальный этап)

- Модуль: `ai.agent`, версия 0.1.0, существующий Manifest v2 и image digest.
- Ядро и его привилегированный helper обновляются совместно.
- Helper разрешает только фиксированные `nvr.module` и `ai.agent` для
  read-only операции `docker.module.endpoint`. Проверяются Docker labels
  `home-ai.managed=true`, точный module ID, запущенное состояние и ID
  управляемой Docker-сети. Core не открывает `docker.sock`.
- Core читает `access-token` через `os.OpenRoot` из каталога
  `/var/lib/home-ai-modules/ai.agent` (или тестового переопределения).
  Требуется регулярный закрытый файл. **Токен никогда не возвращается в браузер.**
- Browser → Core: сессия Home-AI-Core, права `modules.manage`;
  cookie-модификации требуют CSRF. Админские маршруты `/api/v1/ai/…`
  имеют фиксированный список разрешённых операций.
- Core → AI: только адрес контейнера, подтверждённый helper, и порт 8080,
  без перенаправлений, внешнего HTTP proxy, браузерных cookies или JWT.
  Запросы и ответы ограничены по размеру и времени. Из ответа наружу выдаётся
  только JSON; внутренние ошибки модуля и секреты не передаются.
- В аудите фиксируется тип админской операции, но **не** запросы пользователя,
  содержимое ответов, API-ключи или private token.

## Веб-панель

`/modules/ai.agent` — нативная React-страница в общем интерфейсе Core:

1. Чат и история разговоров.
2. AI-провайдеры: Ollama, OpenAI, OpenAI-compatible.
3. Подтверждения потенциально опасных действий.

Подтверждение остаётся `approved_not_executed`; **запуск операций ядра AI
ещё не реализован**. Прямой доступ к AI контейнеру через внешний порт не нужен.

## Ограничение для безопасности

В версии AI-модуля 0.1.0 история и настройки провайдеров сохраняются в одной
базе для всего модуля. Раздел **доступен только пользователям с
`modules.manage`**. Перед открытием для членов семьи и отдельных ролей
нужна полноценная изоляция истории/провайдеров по пользователям.

Это изменение ядра, не обновление Docker-образа AI. Новый UI появится на
рабочем сервере только после установки релиза Core с обновлёнными backend,
helper и веб-клиентом. Изменения в GitHub сами по себе не меняют сервер.

## Диагностика

При отсутствии модуля/выключенном контейнере сервер отдаёт `ai_not_running`.
При недоступности адреса/токена/контейнера — `ai_unavailable`.
Проверьте в «Модули → Установленные», что `ai.agent` имеет статус
`enabled`, а в «Модули → Настройки» — что Docker и сеть готовы.
Секретный файл не нужно копировать в браузер или передавать в чат.
