# HOME AI Core — упрощённое добавление диска

**Дата:** 13 октября 2026 г.  
**Статус:** черновая реализация в отдельном PR, не развёрнута на сервере.

## Интерфейс

Раздел **Система → Хранилище → Диски** теперь может показать кнопку
**«Подключить диск»** для двух безопасно распознаваемых случаев:

1. Пустой несистемный диск, без файловой системы, разделов и таблицы разделов:
   пользователь задаёт необязательное имя, подтверждает точный путь устройства;
   Core создаёт один раздел на всё свободное место, форматирует ext4,
   монтирует и назначает для раздела «Файлы».
2. Несистемный диск с единственным не смонтированным разделом ext4/XFS:
   Core монтирует существующий раздел без форматирования и назначает его для файлов.

Все остальные ситуации остаются в расширенных инструментах разметки.
В частности, мастер не используется для системных дисков, накопителей
с несколькими разделами, сигнатурами RAID/LVM или уже смонтированных устройств.

## Меры предосторожности

- Перед операцией выполняется повторная инвентаризация и сверка модели, serial,
  ёмкости и пути устройства.
- Требуется подтверждение точного пути и отдельное согласие с предупреждением.
- Все вызываемые операции проходят существующие API, проверки прав, dry-run и audit.
- Новый флаг `require_blank` проверяется привилегированным helper и во время
  предварительной проверки, и непосредственно перед созданием раздела.
  `lsblk` должен сообщить полностью пустой диск без дочерних устройств;
  `wipefs --no-act` не должен обнаружить ни одной сигнатуры.
- При отсутствии надёжно определённого нового раздела мастер прекращает работу,
  не выполняя форматирование.
- Протокол helper повышен с 7 до 8, чтобы старый helper не проигнорировал
  обязательную проверку пустого диска.

## Ограничения, требующие следующего этапа

- Существующая операция mount в Core монтирует файловую систему на текущий сеанс,
  но **не создаёт постоянное правило монтирования для перезапуска сервера**.
  Автоматический remount по UUID нужно реализовать и проверить отдельно.
- Для существующих разделов сохраняется существующее содержимое, но
  резервная копия не создаётся.
- Если процесс прерывается после создания раздела, возможна частично
  завершённая конфигурация. Интерфейс уведомляет об этом; автоматический
  повтор без проверки запрещён.
- Перед merge необходимы CI и live-тесты на отдельном Debian-узле,
  включая пустой диск, повторное подключение и отказоустойчивость.
