# Восстановление установки NVR без GHCR-токена

## Причина

Официальный каталог в `DeadSoulf/home-ai-core_modules` содержит `nvr.module`
версии `1.1.1` с неизменяемой ссылкой:

`ghcr.io/deadsoulf/home-ai-core-nvr@sha256:9f89c074832380b9e7cf9cdd41454ceffa5c2bdb364cdb6be45f02de6f9910d1`

Образ действительно публиковался из открытого репозитория
[home-ai-core_dvr](https://github.com/DeadSoulf/home-ai-core_dvr);
публикация в GitHub Actions 7 октября 2026 завершилась успешно. Но
анонимное скачивание пакета сейчас возвращает GHCR `unauthorized`.
Это отдельное право GHCR, не зависящее от публичности репозитория.

Исходный репозиторий **уже содержит** бинарные файлы стороннего Hikvision
HCNetSDK. Условия его внешнего распространения не подтверждены; не стоит
делать образ публичным, не выяснив права. В режиме восстановления Core
ничего не публикует в GHCR.

## Ограниченное восстановление

1. Core пытается скачать исходный image по опубликованному `@sha256`.
2. Если GHCR прямо отказал из-за доступа/отсутствия манифеста, fallback
   разрешается **только** при точном совпадении идентификатора модуля
   `nvr.module` и прежнего SHA-256 образа из каталога.
3. Docker получает удалённый Git-контекст из
   `https://github.com/DeadSoulf/home-ai-core_dvr.git#1793b39553c4aac37fd7a468db93e170c9e616d2`.
   Именно этот коммит создал опубликованный манифест GHCR.
4. Core строит NVR **локально на сервере**. Новые слои остаются в локальном
   Docker-хранилище, и ни один из SDK-компонентов не публикуется публично
   этим механизмом.
5. Перед созданием контейнера Core получает полный `sha256:` **ID локального
   образа** из Docker. Контейнер создаётся по этому ID, а не по
   перезаписываемому тегу. Контейнер маркируется исходным GHCR digest и
   ревизией Git; при повторной попытке совпадения строго проверяются.
6. Данные модуля сохраняются в прежнем каталоге
   `/var/lib/home-ai-modules/nvr.module`. Для уже существующего контейнера
   по-прежнему применяется безопасная проверка идентичности и перезапись
   работающего контейнера запрещена.

**ВАЖНО:** локально собранный образ не обязан иметь тот же Docker *image ID*,
что у GHCR-манифеста: исходный образ зафиксирован манифестом, а
восстанавливаемая сборка — исходным Git-коммитом. Эта ветка строго ограничена
одним исторически проверенным NVR digest и не заменяет проверку подписанных
каталогов для будущих модулей. Она не используется при ошибках сети,
сертификата или произвольных адресах из ручного манифеста.

Поскольку Docker-сборка из исходников требует Ubuntu apt и GitHub,
первый запуск может занять несколько минут. Требуются доступ к GitHub,
Docker, apt-репозиториям и Linux amd64. GitHub-образы базовой Ubuntu и пакеты
apt также должны быть доступны без токенов.

## Проверки

- Регрессионные Go-тесты используют поддельную команду Docker и проверяют
  отказ при чужом образе, ошибке сети, недопустимом image ID, корректном
  локальном запуске, метки provenance и восстановлении после обрыва.
- Workflow `NVR pinned source fallback smoke` запускает настоящую
  одноразовую сборку из закреплённого Git-контекста и проверяет HTTP status
  NVR на изолированном GitHub runner. У workflow нет доступа
  `packages: write` и он не выполняет `docker push`.
- Рабочий сервер и его файлы не изменяются до отдельного решения
  администратора установить обновление и повторить модульную установку.

## Ограничения и дальнейшее решение

В идеале NVR должен публиковаться в доступном клиентам реестре с
неизменяемым подписанным digest. Для будущих NVR-версий нужна полноценная
проверенная публикация, законный канал распространения Hikvision SDK и
синхронизация digest с каталогом. Не следует просто переписывать digest
на другой образ, делать SDK публичным или скачивать любой URL по
непроверенному полю манифеста.
